# API 설계 및 구현 체크리스트

아래 경로와 형식은 팀의 초기 구현 계획입니다. 기능을 구현할 때 이 문서에서 체크리스트를 갱신하고, 실제 요청·응답이 달라지면 예시도 함께 수정합니다. 대화 기능은 로그인한 사용자만 사용할 수 있어야 합니다.

## 시스템 상태 확인

- [x] `GET /health`: 서비스 상태 확인 (현재 초기 앱에 구현)

응답 예시 `200 OK`:

```json
{
  "status": "ok",
  "service": "next-star-hunter"
}
```

## 인증

- [ ] `POST /api/auth/register`: 회원가입 및 비밀번호 해시 저장
- [ ] `POST /api/auth/login`: 로그인 및 인증 상태 생성
- [ ] 비로그인 사용자의 대화 API 접근 차단

회원가입 요청 예시:

```json
{
  "email": "user@example.com",
  "password": "사용자가 입력한 비밀번호"
}
```

비밀번호 원문은 DB나 응답에 저장·포함하지 않습니다. 중복 계정과 인증 실패는 사용자에게 이해 가능한 오류로 반환합니다.

## 채팅 및 기록

- [ ] `POST /api/chat`: 질문 검증, AI API 호출, 응답 및 로그 저장
- [ ] 최근 대화를 이용해 같은 사용자의 문맥 유지
- [ ] `GET /api/me/chats`: 로그인한 사용자의 대화 기록 조회
- [ ] AI 실패·시간 초과 시 오류 안내와 서버 로그 기록

질문 요청 예시:

```json
{
  "message": "안경을 쓴 부산 출신 아이돌을 추천해줘"
}
```

성공 응답 예시:

```json
{
  "chat_id": 1,
  "answer": "조건에 맞는 스타를 찾아볼게요.",
  "created_at": "2026-10-29T12:00:00Z"
}
```

대화 기록 조회 결과에는 질문, 응답, 생성 시각을 포함합니다. 사용자는 자신의 기록만 조회할 수 있어야 합니다. 상세 오류 코드와 인증 방식을 정하면 이 문서에 반영합니다.
